# Use the skill authoring owner

Use when a selected opportunity concerns skill content, activation or a candidate skill. Resolve one available authoring owner whose instructions cover the requested work. In this Codex session, `skill-creator` covers creation and updates. The managed `write-a-skill` currently describes creation; do not assume identical coverage in every environment.

Pass the target skill, evidence, accepted behavior, scope, permitted action, intended environments and expected return. Let the owner supply its criteria for metadata, content, references and validation. Do not copy another authoring manual into Reflect or load multiple authors to combine their rules.

The owner may guide unresolved domain questions through the [shared interview protocol](questionnaire.md). Reuse prior answers, keep one active question and record decisions in the same review. Review-only input does not authorize edits; candidate edits remain outside active installations.

For a selection issue, distinguish not selected from loaded but executed incorrectly. Inspect the actual catalog, exposed metadata, version, invocation policy and available traces. Ask the authoring owner to assess triggers, body consistency and overlap; request [evaluation](failure-evaluation.md) for natural positive and nearby negative cases. A source file or explicit invocation does not prove automatic selection.

Correct the responsible skill or discovery configuration as a proposal, without adding compensating selectors to AGENTS.md. Return findings, the owner used, candidate artifacts, performed checks and gaps. If no suitable owner is available, report that dependency instead of silently implementing an unreviewed substitute.
